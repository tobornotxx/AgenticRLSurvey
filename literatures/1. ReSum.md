## 2. 研究背景与动机

### 2.1 LLM Web Agent 的兴起

大语言模型 (LLM) 驱动的 Web 智能体在知识密集型搜索任务中展现出强大的能力。以 ReAct 范式为代表的方法，通过将思考 (thought)、动作 (action) 和观察 (observation) 不断追加到上下文历史中，实现了智能体的迭代推理与交互。然而，这种方法存在一个根本性矛盾：**长程搜索所需的充分探索与有限上下文窗口之间的冲突**。

### 2.2 上下文窗口瓶颈

在实际的 Web 搜索任务中，智能体需要经历大量的搜索-浏览-推理循环。每一轮交互都会向上下文中追加新的内容，导致上下文长度迅速膨胀。论文对 WebSailor-7B 在 BrowseComp 基准上的实验分析表明，**失败的搜索轨迹频繁超过 32K token 的上下文限制**，使得智能体被迫在尚未找到答案时便截断搜索过程。这一现象说明，上下文窗口的限制直接制约了智能体的搜索能力和最终性能。

### 2.3 现有方案的局限

当前解决上下文瓶颈的方案主要依赖**架构修改**，典型代表包括：

- **MEM1**：在模型内部引入 memory token 机制，将历史信息压缩到特殊的内存标记中
- **MemAgent**：通过修改模型架构实现内部记忆管理

这些方法虽然在一定程度上缓解了上下文限制问题，但存在严重的实用性瓶颈：

1. **兼容性破坏**：架构修改导致无法直接应用于已有的预训练智能体
2. **高昂的重训练成本**：需要端到端地重新训练整个模型
3. **前向兼容性差**：随着基础模型的迭代更新，架构修改方案需要反复适配

### 2.4 ReSum 的核心动机

ReSum 的设计动机在于提供一种**范式级别的增强 (paradigmatic enhancement)**，而非架构级别的修改。具体而言：

- 利用**上下文摘要 (context summarization)** 机制压缩历史轨迹
- 保持与现有智能体的完全兼容
- 实现免训练 (training-free) 的即插即用能力
- 同时支持通过强化学习进一步优化

## 3. 研究问题

本文聚焦于以下核心研究问题：

> **如何在不修改智能体架构的前提下，突破上下文窗口对 LLM Web 智能体长程搜索能力的限制？**

具体细化为以下子问题：

1. **上下文压缩**：如何在不丢失关键搜索信息的前提下，有效压缩智能体的交互历史？
2. **免训练适用性**：如何设计一种无需重新训练即可提升现有智能体性能的方案？
3. **RL 训练兼容性**：如何将上下文摘要机制与强化学习训练流程 (如 GRPO) 有机结合？
4. **数据效率**：能否以极少量的训练数据 (如 1K 样本) 实现显著的性能提升？
5. **可扩展性**：该方案能否在不同规模的模型 (3B/7B/30B) 和不同上下文长度 (32K/128K) 下保持有效？

## 4. 基本假设

论文的方法建立在以下基本假设之上：

### 4.1 信息冗余假设

在长程搜索过程中，智能体积累的交互历史包含大量冗余信息。早期的搜索尝试、失败的路径探索、重复的网页内容等，并不需要以原始形式全部保留。一个高质量的摘要能够保留关键发现和搜索进展，同时大幅缩减上下文占用。

### 4.2 摘要保真假设

经过摘要压缩后的上下文 $q' = (q, s)$（其中 $q$ 为原始查询，$s$ 为摘要）能够保留足够的信息，使智能体继续有效地推进搜索任务。即摘要过程不会丢失对后续决策至关重要的关键信息。

### 4.3 范式可分离假设

上下文管理可以作为一个独立的、偶发性的功能模块，与智能体的核心推理和决策过程解耦。ReSum 作为一个"偶发性上下文管理器 (occasional context manager)"，而非紧密集成的规划器 (closely integrated planner)，不需要深度嵌入智能体的推理链路。

### 4.4 奖励广播假设

在 ReSum-GRPO 训练中，论文假设整个轨迹的最终奖励信号可以均匀广播到因摘要事件而分割的各个片段上。即每个片段对最终成功或失败的贡献是等价的，可以共享同一个优势估计值。

### 4.5 教师模型一致性假设

大规模教师模型 (如 GPT-OSS-120B) 在长程任务中能够保持更好的目标一致性 (goal consistency)，因此其生成的摘要质量优于较小规模的模型。

## 5. 遇到的困难与挑战

### 5.1 上下文窗口的硬性限制

ReAct 范式将每一步的 $(\tau_t, a_t, o_t)$ 三元组追加到历史中，上下文长度随交互步数线性增长。在 32K 上下文限制下，WebSailor-7B 在 BrowseComp 上的失败轨迹频繁触及上限，导致智能体被迫提前终止搜索。

### 5.2 摘要质量与搜索效果的权衡

摘要需要在压缩率和信息保留之间取得平衡：
- **过于精简**：可能丢失关键线索，导致智能体在后续搜索中重复已失败的路径
- **过于冗长**：压缩效果不明显，无法有效释放上下文空间

### 5.3 RL 训练中的轨迹分段问题

将摘要事件引入 RL 训练流程带来了独特的挑战：
- 摘要操作将完整轨迹切分为多个片段，每个片段构成独立的训练 episode
- 需要设计合理的奖励分配机制，将终端奖励回传到各片段
- 训练效率因片段数量增加而下降

### 5.4 免训练场景下的摘要能力获取

在免训练设置下，需要寻找合适的摘要执行者：
- 直接使用智能体自身进行摘要效果不佳
- 使用大型外部模型 (如 GPT-OSS-120B) 成本高昂
- 需要训练专门的轻量级摘要模型 (ReSumTool)

### 5.5 训练数据效率

如何以极少量的监督数据 (1K 样本) 训练出有效的 RL 策略，是实际部署中的关键挑战。

### 5.6 格式约束的严格性

智能体必须遵循特定的格式规范（如 `<answer>` 标签），格式违规将导致整个轨迹获得零奖励，增加了训练的不稳定性。

## 6. 提出的算法解决方案

### 6.1 ReSum 范式总览

ReSum 提出了一种基于上下文摘要的搜索智能体范式，核心思想是在交互过程中周期性地将历史轨迹压缩为摘要，从而释放上下文空间以支持更长程的搜索。

#### 6.1.1 轨迹初始化 (Trajectory Initialization)

给定用户查询 $q$，初始化历史为：

$$H_0 = (q)$$

#### 6.1.2 迭代交互 (Iterative Interaction)

在每一步 $t$，智能体基于当前历史生成思考和动作：

$$(\tau_t, a_t) \sim \pi_\theta(\cdot \mid H_{t-1})$$

其中 $\tau_t$ 为思考 (thought)，$a_t$ 为动作 (action)，$\pi_\theta$ 为智能体策略。

#### 6.1.3 历史更新 (History Update)

执行动作后获得观察 $o_t$，将三元组追加到历史中：

$$H_t = H_{t-1} \circ (\tau_t, a_t, o_t)$$

其中 $\circ$ 表示拼接操作。

#### 6.1.4 上下文摘要 (Context Summarization)

当触发条件 (trigger) 被激活时（例如上下文长度超过预设阈值），执行摘要操作：

$$s \sim \pi_{\text{sum}}(\cdot \mid H_t)$$

随后将历史重置为压缩状态：

$$q' = (q, s)$$
$$H_t \leftarrow (q')$$

其中 $\pi_{\text{sum}}$ 为摘要策略（可以是外部大模型、专门训练的摘要模型或智能体自身），$s$ 为生成的摘要，$q'$ 为由原始查询和摘要构成的新起点。

#### 6.1.5 轨迹终止 (Trajectory Termination)

当智能体判断已获得足够信息时，在 `<answer>` 标签中生成最终答案，终止搜索过程。

### 6.2 ReSumTool-30B：专用摘要模型

ReSumTool-30B 是论文训练的专用上下文摘要模型，用于在免训练设置下为智能体提供高质量的摘要服务。其训练采用三阶段流水线：

#### 6.2.1 阶段一：教师模型选择 (Teacher Model Selection)

论文评估了多个候选模型作为摘要教师，最终选择 **GPT-OSS-120B**，原因是该模型在长程任务中展现出**更优的目标一致性 (goal consistency)**。具体而言，GPT-OSS-120B 在生成摘要时能更好地保持与原始搜索目标的对齐，避免信息偏移。

#### 6.2.2 阶段二：数据合成 (Data Synthesis)

利用选定的教师模型，在 **SailorFog-QA** 基准上记录 ReSum 搜索轨迹，收集完整的对话-摘要数据对：

- 运行智能体在 SailorFog-QA 上执行搜索任务
- 在每个摘要触发点，使用 GPT-OSS-120B 生成高质量摘要
- 最终获得 **9000+** 高质量的 $\langle \text{Conversation}, \text{Summary} \rangle$ 数据对

#### 6.2.3 阶段三：模型开发 (Development)

基于收集到的数据，对基础模型进行微调：

| 超参数 | 设置 |
|--------|------|
| **基础模型** | Qwen3-30B-A3B-Thinking |
| **批量大小** | 64 |
| **训练轮数** | 2 epochs |
| **学习率** | $7 \times 10^{-6}$ |

微调后得到的 ReSumTool-30B 能够以远低于 GPT-OSS-120B 的推理成本，提供接近教师模型质量的摘要能力。

### 6.3 ReSum-GRPO：强化学习训练方案

ReSum-GRPO 是论文的核心算法贡献，将 ReSum 范式与 Group Relative Policy Optimization (GRPO) 强化学习方法相结合，实现端到端的策略优化。

#### 6.3.1 轨迹分段 (Trajectory Segmentation)

在一条完整的搜索轨迹中，假设发生了 $K$ 次摘要事件，则轨迹被自然地分割为 $K+1$ 个片段。

第 $i$ 个片段的形式为：

$$H^{(1)} = \left(q^{(0)},\; \tau_1, a_1, o_1,\; \ldots,\; \tau_{t_1}, a_{t_1}, o_{t_1}\right)$$

更一般地，第 $i$ 个片段 $H^{(i)}$ 以前一次摘要生成的压缩查询 $q^{(i-1)}$ 作为输入起点，包含该片段内所有的交互步骤，直到下一次摘要事件或轨迹终止。

每个片段 $H^{(i)}$ 构成一个**独立的训练 episode**，其输入为对应的压缩查询 $q^{(i-1)}$。

#### 6.3.2 奖励函数 (Reward Function)

论文采用基于 LLM-as-Judge 的二值奖励函数：

$$R(a^*, a_T) \in \{0, 1\}$$

其中 $a^*$ 为标准答案，$a_T$ 为智能体生成的最终答案。由 LLM 评判器判断答案的正确性，输出 0（错误）或 1（正确）。

**格式约束**：如果智能体在轨迹中未能遵循格式规范（如未使用正确的格式标记 token），则整条轨迹的奖励被强制设为零：

$$R = 0 \quad \text{if format tokens are violated}$$

#### 6.3.3 优势广播 (Advantage Broadcasting)

在 GRPO 框架下，对于一个 group 内的第 $g$ 条轨迹，其归一化优势值计算为：

$$\hat{A}_g = \frac{R_g - \text{mean}(\{R_1, \ldots, R_G\})}{\text{std}(\{R_1, \ldots, R_G\})}$$

其中 $G$ 为 group 大小，$R_g$ 为第 $g$ 条轨迹的最终奖励。

**关键设计**：由于摘要事件将轨迹分割为多个片段，论文将整条轨迹的优势值**均匀广播**到所有片段：

$$\hat{A}_g^{(i)} = \hat{A}_g, \quad \forall i \in \{1, \ldots, K+1\}$$

即每个片段共享相同的优势估计值，不进行片段级别的差异化信用分配。

#### 6.3.4 GRPO 目标函数 (GRPO Objective)

ReSum-GRPO 的优化目标为：

$$J_{\text{GRPO}}(\theta) = \mathbb{E}\left[\frac{1}{\sum n_g} \sum_g \sum_i \min\left(r_g^{(i)}(\theta) \cdot \hat{A}_g^{(i)},\; \text{clip}\left(r_g^{(i)}(\theta),\; 1 - \varepsilon_{\text{low}},\; 1 + \varepsilon_{\text{high}}\right) \cdot \hat{A}_g^{(i)}\right)\right]$$

其中：
- $r_g^{(i)}(\theta) = \frac{\pi_\theta(a \mid s)}{\pi_{\theta_{\text{old}}}(a \mid s)}$ 为第 $g$ 条轨迹第 $i$ 个片段的重要性采样比率
- $\varepsilon_{\text{low}}, \varepsilon_{\text{high}}$ 为 PPO 风格的裁剪参数
- $n_g$ 为第 $g$ 条轨迹的片段内 token 总数
- 外层求和遍历 group 内所有轨迹 $g$，内层求和遍历每条轨迹的所有片段 $i$

该目标函数在标准 GRPO 的基础上，通过对分段轨迹的联合优化和优势广播，实现了对 ReSum 范式的端到端强化学习训练。

### 6.4 摘要提示词设计 (Prompt for Context Summarization)

论文为摘要模型设计了专门的提示词模板，核心指令为：

> "You are an expert at analyzing conversation history and extracting relevant information..."

提示词包含以下指导原则：
- **信息分析 (Information Analysis)**：全面分析对话历史，识别关键发现、搜索进展和已排除的假设
- **摘要要求 (Summary Requirements)**：确保摘要保留与搜索目标相关的所有关键信息，同时去除冗余内容
- **输出格式 (Output Format)**：使用 `<summary>` 标签包裹摘要输出，便于程序化解析

## 7. 工具环境设计

### 7.1 搜索工具 (Search Tool)

- **功能**：向 Google Search 发送查询请求
- **返回结果**：每次查询返回 **top-10** 搜索结果
- **用途**：智能体通过构造不同的搜索查询来探索信息空间

### 7.2 浏览工具 (Visit Tool)

- **功能**：浏览指定的网页 URL
- **底层技术**：使用 **Jina** 进行网页内容抓取和渲染
- **信息提取**：使用 **Qwen2.5-72B-Instruct** 从网页中提取与搜索目标相关的证据信息
- **用途**：智能体在定位到候选网页后，使用该工具深入浏览并提取关键信息

### 7.3 工具调用预算

- **最大工具调用次数**：60 次（标准设置）
- 在 128K 上下文实验中，工具调用次数扩展至 40/60/80/120 次

### 7.4 工具交互流程

智能体在每一步中选择一个工具执行：
1. 思考当前搜索进展和下一步策略 ($\tau_t$)
2. 选择并构造工具调用动作 ($a_t$)
3. 接收工具返回的观察结果 ($o_t$)
4. 将三元组追加到历史中，或在触发条件下执行摘要

## 9. 实验结果与分析

### 9.1 免训练结果 (Training-free Results, Table 1)

| 方法 | 智能体 | GAIA | BC-zh | BC |
|------|--------|------|-------|-----|
| ReAct | WebSailor-30B | 45.0 | 23.9 | 12.8 |
| ReSum + ReSumTool | WebSailor-30B | 47.3 | 24.1 | 16.0 |
| ReSum + GPT-OSS-120B | WebSailor-30B | **51.5** | **27.3** | **18.8** |
| MEM1 | 30B (仅支持) | 33.3 | 25.0 | 12.7 |

**分析**：
- ReSum + GPT-OSS-120B 在三个基准上全面超越 ReAct 基线，GAIA 提升 6.5 点，BC 提升 6.0 点
- ReSumTool 作为轻量级替代方案，在 BC 上也实现了 3.2 点的提升
- MEM1 在 GAIA 上表现显著低于 ReAct（33.3 vs 45.0），表明架构修改可能对部分任务产生负面影响
- MEM1 在 BC-zh 上略高于 ReAct（25.0 vs 23.9），但整体表现不及 ReSum

| 方法 | 智能体 | GAIA | BC-zh | BC |
|------|--------|------|-------|-----|
| GRPO (ReAct) | WebSailor-30B | 48.2 | 23.3 | 14.3 |
| ReSum-GRPO | WebSailor-30B | 48.5 | **33.3** | 18.3 |
| MEM1-GRPO | WebSailor-30B | 35.7 | 29.1 | **19.5** |
| ReSum-GRPO | WebSailor-3B | - | 20.5 | - |
| GRPO (ReAct) | WebSailor-3B | - | 8.2 | - |

**分析**：
- ReSum-GRPO 在 BC-zh 上实现了显著提升：从 23.3 (GRPO) 提升至 33.3，绝对提升 10.0 点（+42.9%）
- WebSailor-3B 上 ReSum-GRPO 的表现尤为突出：BC-zh 从 8.2 提升至 20.5，提升幅度达 **150%**
- MEM1-GRPO 在 BC 上略优于 ReSum-GRPO（19.5 vs 18.3），但在 GAIA 上表现极差（35.7）
- **数据效率极高**：ReSum-GRPO 仅使用 **1K 训练样本** 即实现了显著性能提升

### 9.3 128K 上下文实验 (Table 3)

使用 **Tongyi-DeepResearch-30B-A3B**（128K 上下文）进行实验：

| 工具调用次数 | ReAct (BC) | ReSum (BC) | 提升 |
|-------------|-----------|-----------|------|
| 40 | 27.7 | **34.5** | +6.8 |
| 60 | 32.8 | **38.2** | +5.4 |
| 80 | 36.3 | **40.3** | +4.0 |
| 120 | 42.2 | **44.5** | +2.3 |

**分析**：
- 即使在 128K 上下文下，ReSum 依然在所有工具调用预算设置中保持一致的优势
- 随着工具调用次数增加（即上下文压力增大），两者的绝对差距有所缩小但 ReSum 始终领先
- 在 40 次工具调用时提升最为显著 (+6.8)，说明 ReSum 在上下文资源更紧张时价值更大
- 该结果证明 ReSum 不仅适用于短上下文场景，在长上下文条件下同样有效

### 9.4 训练效率 (Training Efficiency, Table 4)

每训练步的耗时对比：

| 模型 | GRPO (h/step) | ReSum-GRPO (h/step) | 额外开销 |
|------|--------------|---------------------|----------|
| WebSailor-3B | 0.62 | 1.05 | +69.4% |
| WebSailor-7B | 0.96 | 1.44 | +50.0% |
| WebSailor-30B | 0.94 | 1.25 | +33.0% |

**分析**：
- ReSum-GRPO 相比标准 GRPO 增加约 **33%-69%** 的训练时间
- 额外开销主要来自：摘要模型的调用、轨迹分段后的多 episode 处理、更多的工具调用次数 (60 vs 40)
- 模型越大，相对额外开销越小（30B: +33% vs 3B: +69%）
- 考虑到性能提升幅度（BC-zh: +42.9%），训练开销的增加是可接受的

### 9.5 推理成本分析

| 方法 | 相对 Token 消耗 | 说明 |
|------|----------------|------|
| ReAct | 1x | 基线 |
| ReSum | ~2x | 摘要模型额外调用 |
| MEM1-GRPO | ~3x (相对 ReSum) | 内存机制开销 |

**分析**：
- ReSum 的推理成本约为 ReAct 的 2 倍，主要来自摘要模型的额外调用
- MEM1-GRPO 的 token 消耗约为 ReSum 的 3 倍，但仅带来约 1.2% 的性能提升
- 从性价比角度，ReSum 的成本-效益比远优于 MEM1-GRPO

## 10. 与相关工作的对比

### 10.1 Web Agent 相关工作

| 工作 | 方法类型 | 特点 |
|------|----------|------|
| **WebSailor** | 基础搜索智能体 | ReAct 范式，ReSum 的基线智能体 |
| **WebShaper** | Web 交互智能体 | 侧重于 Web 页面交互 |
| **ASearcher** | 搜索增强智能体 | 优化搜索策略 |
| **WebExplorer** | Web 探索智能体 | 强调探索-利用平衡 |
| **DeepDive** | 深度搜索智能体 | 多轮深度搜索 |

ReSum 与这些工作的关系是**正交的**：ReSum 作为上下文管理范式，可以应用于任何基于 ReAct 的 Web 智能体之上。

### 10.2 上下文管理相关工作

#### 外部记忆方法 (External Memory)

| 工作 | 方法 | 与 ReSum 的区别 |
|------|------|----------------|
| **A-MEM** | 自适应外部记忆 | 需要额外的记忆检索机制 |
| **MemOS** | 记忆操作系统 | 系统级记忆管理，复杂度高 |
| **ReasoningBank** | 推理知识库 | 存储推理中间结果 |

#### 内部记忆方法 (Internal Memory with RL)

| 工作 | 方法 | 与 ReSum 的区别 |
|------|------|----------------|
| **MEM1** | 内部 memory token | **需要架构修改**，破坏兼容性 |
| **MemAgent** | 内部记忆智能体 | **需要端到端重训练** |
| **MemSearcher** | 记忆增强搜索 | 深度整合记忆与搜索 |

### 10.3 ReSum 的关键区分

| 维度 | ReSum | 架构修改方法 (MEM1 等) |
|------|-------|----------------------|
| **修改类型** | 范式级增强 | 架构级修改 |
| **兼容性** | 与现有智能体完全兼容 | 破坏兼容性 |
| **免训练能力** | ✅ 即插即用 | ❌ 需要重训练 |
| **数据效率** | 1K 样本即可 RL 训练 | 通常需要更多数据 |
| **前向兼容性** | ✅ 随基础模型升级 | ❌ 需要重新适配 |
| **角色定位** | 偶发性上下文管理器 | 紧密集成的组件 |

### 10.4 与世界模型增强智能体的区分

论文明确指出 ReSum 与世界模型增强智能体 (world-model-augmented agents) 有本质区别：
- 世界模型方法试图构建环境的内部表示以辅助规划
- ReSum 不构建世界模型，仅在上下文层面进行压缩管理
- ReSum 作为偶发性触发的上下文管理器，不参与智能体的核心推理和规划过程

## 11. 可能的欠缺与不足

### 11.1 摘要信息损失

尽管 ReSum 通过摘要压缩释放了上下文空间，但摘要过程不可避免地会造成一定程度的信息损失。特别是在需要精确回忆细节信息的任务中，摘要可能导致关键细节的遗漏。论文未对信息损失进行定量分析。

### 11.2 优势广播的粗粒度

ReSum-GRPO 将整条轨迹的优势值均匀广播到所有片段（$\hat{A}_g^{(i)} = \hat{A}_g$），这一设计假设所有片段对最终结果的贡献是等价的。然而实际上，某些片段可能包含关键的发现步骤，而另一些片段可能是无效的探索。更精细的信用分配机制（如基于片段级别的价值估计）可能带来进一步的性能提升。

### 11.3 推理成本翻倍

ReSum 的推理 token 消耗约为 ReAct 的 2 倍，在大规模部署场景下，这一额外成本不可忽视。尽管相比 MEM1-GRPO 的 3 倍消耗更为经济，但仍然是一个需要关注的实际问题。

### 11.4 摘要触发策略的简化

论文主要基于上下文长度阈值来触发摘要操作，这一策略相对简化。更智能的触发机制（如基于信息增益、搜索进展评估或智能体不确定性的自适应触发）可能进一步提升效率。

### 11.5 评估基准的局限

实验主要在 GAIA、BrowseComp 和 BrowseComp-zh 三个基准上进行评估。这些基准虽然具有代表性，但可能无法完全覆盖真实 Web 搜索场景的多样性。缺乏在更广泛任务类型（如多步推理、长文档理解、实时信息搜索等）上的评估。

### 11.6 对摘要模型的依赖

在免训练设置下，ReSum 的性能高度依赖于摘要模型的质量。使用 GPT-OSS-120B 可获得最佳效果，但这引入了对大型外部模型的依赖。ReSumTool-30B 虽然降低了成本，但性能有所下降（BC: 16.0 vs 18.8）。

### 11.7 训练效率的额外开销

ReSum-GRPO 增加了 33%-69% 的训练时间，对于计算资源有限的研究者而言，这一额外开销可能构成实际瓶颈。

### 11.8 缺乏消融研究的深度

论文对以下方面的消融研究不够充分：
- 摘要长度对性能的影响
- 摘要频率（触发阈值）的敏感性分析
- 不同摘要提示词设计的对比
- 优势广播 vs 差异化信用分配的对比

### 11.9 格式约束的严格惩罚

格式违规导致整条轨迹零奖励的设计过于严格，可能在训练早期造成大量有效信息的浪费，影响训练稳定性和收敛速度。

## 12. 总结

### 12.1 核心贡献

ReSum 提出了一种基于上下文摘要的搜索智能体范式增强方案，其核心贡献包括：

1. **ReSum 范式**：通过周期性的上下文摘要-重置机制，突破了 LLM Web 智能体的上下文窗口限制，使智能体能够执行更长程的搜索探索
2. **ReSumTool-30B**：基于 9000+ 高质量数据对训练的专用摘要模型，以较低成本提供高质量的上下文压缩服务
3. **ReSum-GRPO**：将 ReSum 范式与 GRPO 强化学习无缝结合的训练算法，通过轨迹分段和优势广播实现端到端优化
4. **范式级兼容性**：ReSum 作为范式级增强而非架构修改，保持了与现有智能体的完全兼容和前向兼容性

### 12.2 实验结论

- 免训练设置下，ReSum + GPT-OSS-120B 在 BrowseComp 上实现了 47% 的相对提升（12.8 → 18.8）
- RL 训练下，ReSum-GRPO 仅用 1K 样本即在 BC-zh 上实现 43% 的相对提升（23.3 → 33.3）
- 小模型（3B）同样受益显著，BC-zh 提升 150%（8.2 → 20.5）
- 即使在 128K 上下文下，ReSum 依然保持一致的性能优势
- 推理成本约为 ReAct 的 2 倍，远优于 MEM1 的 6 倍（相对 ReAct）

### 12.3 方法论启示

ReSum 的成功表明，在 LLM Agent 系统中，**"好的工程范式设计"有时比"更复杂的架构创新"更为有效**。上下文管理作为一个可插拔的、与智能体核心逻辑解耦的功能模块，能够以最小的侵入性实现显著的性能提升。这一设计理念对未来 LLM Agent 系统的发展具有重要的指导意义。
