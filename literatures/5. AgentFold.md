# AgentFold: Long-Horizon Web Agents with Proactive Context Management

## 1. 论文基本信息

- **论文标题**: AgentFold: Long-Horizon Web Agents with Proactive Context Management
- **作者**: Rui Ye, Zhongwang Zhang, Kuan Li, Huifeng Yin, Zhengwei Tao, Yida Zhao, Liangcai Su, Liwen Zhang, Zile Qiao, Xinyu Wang, Pengjun Xie, Fei Huang, Siheng Chen, Jingren Zhou, Yong Jiang
- **机构**: Tongyi Lab, Alibaba Group（通义实验室，阿里巴巴集团）
- **发表时间**: 2025年10月
- **论文链接**: arXiv:2510.24699
- **核心贡献**: 提出了一种以**主动上下文管理**为核心的新型智能体范式 AgentFold，通过"折叠"操作在多尺度上管理历史轨迹，使 30B 稀疏激活模型在长程 Web 任务上超越 671B 模型并比肩 OpenAI o4-mini。

---

## 2. 研究背景与动机

### 2.1 长程 Web 任务的核心挑战

基于 LLM 的 Web 智能体在信息检索任务上展现了巨大潜力，但在**长程任务**（long-horizon tasks）中，其有效性受到上下文管理中一个**根本性权衡**的制约。

### 2.2 上下文饱和 vs 信息丢失

当前主流方法面临两难困境：

| 策略 | 方法特征 | 核心问题 |
|------|---------|---------|
| **被动积累** | 基于 ReAct 的智能体逐步累积原始交互历史 | **上下文饱和**（context saturation）：噪声信息不断积累，有效信息被淹没，上下文窗口迅速耗尽 |
| **固定摘要** | 每一步对完整历史进行固定式总结 | **信息不可逆丢失**（irreversible loss）：关键细节在反复总结中被逐步遗忘 |

被动积累策略将上下文视为**被动填充的日志**（passive log to be filled），随着交互步数增长，上下文中充斥着大量冗余的原始观测数据。固定摘要策略虽然控制了上下文长度，但由于每一步都对全量历史重新总结，关键信息的丢失概率随步数呈指数增长。

### 2.3 现有方法的局限

- **ReAct 系列**：上下文线性增长，100 步后上下文可达数万乃至数十万 tokens，远超模型有效处理能力
- **固定摘要方法**：对信息的取舍缺乏自适应能力，无法根据任务进展动态调整保留粒度
- **现有 Web 智能体**（如 WebSailor、ASearcher 等）：在长程基准（如 BrowseComp）上表现受限

## 3. 研究问题

本文聚焦以下核心问题：

> **如何设计一种智能体范式，使其能够主动管理自身的上下文，在控制上下文长度的同时最大限度地保留关键信息，从而在长程 Web 任务中实现持续有效的推理与行动？**

具体分解为：

1. **上下文结构设计**：如何将智能体的上下文组织为一个可被主动塑造的**动态认知工作空间**，而非被动填充的日志？
2. **信息管理策略**：如何让智能体学会在多个尺度上对历史轨迹进行选择性压缩与保留？
3. **可扩展性**：如何使上下文长度随交互步数呈**亚线性增长**，从而支撑数百步的长程交互？
4. **训练方法**：如何训练模型产生结构化的上下文管理响应，而非仅依赖提示工程？

---

## 4. 基本假设

### 4.1 人类认知启发：回顾性巩固

AgentFold 的核心设计灵感来源于人类认知中的**回顾性巩固**（retrospective consolidation）过程：

- 人类在执行长程任务时，不会逐字记忆所有经历的细节
- 而是**主动地**对记忆进行多层次的整理：近期事件保持精细记忆，远期事件压缩为更抽象的要点
- 当发现某段经历对当前任务不再重要时，人类会将其**合并压缩**为概括性记忆
- 当发现某段经历仍然关键时，则**保持其细粒度**

### 4.2 核心假设

1. **认知工作空间假设**：智能体的上下文应被视为一个**动态认知工作空间**（dynamic cognitive workspace），可以被主动塑造（actively sculpted），而非被动填充
2. **多尺度管理假设**：历史信息的重要性随任务进展动态变化，需要在多个粒度尺度上进行管理
3. **共生操作假设**：上下文管理（折叠）与任务执行（行动）应作为**认知共生**（cognitive symbiosis）的统一过程，而非独立的后处理步骤
4. **可学习管理假设**：最优的上下文管理策略可以通过训练习得，而非依赖固定规则或纯提示工程

## 5. 遇到的困难与挑战

### 5.1 信息丢失的概率分析

固定摘要策略中，假设每次重新总结有 1% 的概率丢失某个关键细节：

$$
P(\text{survival after } n \text{ steps}) = 0.99^n
$$

| 步数 $n$ | 关键细节存活概率 |
|-----------|-----------------|
| 10 | $0.99^{10} \approx 90.4\%$ |
| 50 | $0.99^{50} \approx 60.5\%$ |
| 100 | $0.99^{100} \approx 36.6\%$ |
| 500 | $0.99^{500} \approx 0.66\%$ |

这一分析清晰地揭示了**反复总结带来的信息衰减是指数级的**，在长程任务中几乎必然导致关键信息丢失。

### 5.2 结构化输出挑战

即使是最强的 LLM，也无法仅通过提示（prompting）可靠地产生 AgentFold 所需的结构化响应（包含思维链、折叠指令、解释和行动四个部分）。这意味着必须通过训练来实现。

### 5.3 上下文窗口限制

现有模型的上下文窗口虽在扩大（如 128K），但在 ReAct 范式下，100 步交互即可消耗大量上下文空间，严重限制了长程任务的执行能力。

### 5.4 信息粒度的动态权衡

不同时间尺度的历史信息具有不同的价值密度——近期信息需要高粒度保留，远期信息可以压缩，但何时压缩、压缩到何种程度需要根据任务进展动态决定。

## 6. 提出的算法解决方案

### 6.1 AgentFold 上下文设计

AgentFold 将智能体的工作空间（上下文）划分为三个语义区域：

1. **用户问题**（User Question）：不变的任务指令
2. **多尺度状态摘要**（Multi-Scale State Summaries）：长期记忆
3. **最新交互**（Latest Interaction）：即时工作记忆

在第 $t$ 步，上下文 $C_t$ 定义为：

$$
C_t = (Q, T, S_{t-2}, I_{t-1})
$$

其中：

- $Q$：**不变的用户问题**
- $T$：**可用工具集**
- $S_{t-2}$：**多尺度状态摘要**，为有序序列：

$$
S_t = (s_{x_1,y_1}, s_{x_2,y_2}, \ldots, s_{x_m,y_m})
$$

每个 $s_{x,y}$ 是对从步骤 $x$ 到步骤 $y$ 的**连续步骤**的文本摘要，步骤范围构成历史的**完整分区**：

$$
x_1 = 1, \quad y_m = t-2, \quad x_{i+1} = y_i + 1
$$

- 当 $y = x$ 时，$s_{x,x}$ 为**单步摘要**（保持精细粒度）
- 当 $y > x$ 时，$s_{x,y}$ 为**多步合并摘要**（压缩后的粗粒度）

- $I_{t-1}$：**最新交互**，包含上一步的解释、行动和观测：

$$
I_{t-1} = (e_{t-1}, a_{t-1}, o_{t-1})
$$

**初始条件**：

$$
C_1 = (Q, T, \varnothing, \varnothing), \quad C_2 = (Q, T, \varnothing, I_1)
$$

### 6.2 AgentFold 响应结构

在每一步，AgentFold 产生一个**四元组**响应：

$$
R_t = \text{AgentFold}(C_t; \theta) \rightarrow (th_t, f_t, e_t, a_t)
$$

| 组件 | 符号 | 含义 | 描述 |
|------|------|------|------|
| 思维过程 | $th_t$ | Thinking Process | 链式思维独白（chain-of-thought monologue），包含对当前状态的分析和规划 |
| 折叠指令 | $f_t$ | Folding Directive | JSON 格式的上下文管理指令 |
| 解释 | $e_t$ | Explanation | 对当前行动的简洁动机说明 |
| 行动 | $a_t$ | Action | 工具调用或最终答案 |

折叠指令的具体格式为：

$$
f_t = \{\text{"range": } [k, t-1], \text{ "summary": } "\sigma_t"\}
$$

其中 $k$ 决定了折叠的范围和模式。

### 6.3 两种折叠模式

AgentFold 定义了两种核心折叠模式，对应不同的上下文管理需求：

#### 6.3.1 精细凝缩（Granular Condensation）

当 $k = t - 1$ 时触发，仅将**最新交互**折叠为一条新的精细摘要块：

- **操作**：将 $I_{t-1}$ 压缩为单步摘要 $s_{t-1, t-1}$
- **效果**：保留了步骤级别的精细信息，不合并任何之前的摘要块
- **示例**：`'[Compressed Step 5] Found a new candidate XYZ...'`
- **信息保护**：直接缓解了重复总结导致的信息丢失问题，每条信息仅被压缩一次后以独立块形式存在

#### 6.3.2 深度巩固（Deep Consolidation）

当 $k < t - 1$ 时触发，将最新交互与之前的一系列摘要块**融合**为单个粗粒度摘要：

- **操作**：收回 $[k, t-1]$ 范围内的所有摘要块，替换为单个新块 $s_{k, t-1} = \sigma_t$
- **效果**：大幅压缩上下文长度，将多步探索合并为概括性结论
- **示例**：`'[Compressed Step 5 to 9] Confirmed that XYZ does not fit...'`
- **适用场景**：当模型判断某段探索已经得出结论（无论成功还是失败）时，将其压缩为总结性陈述

#### 6.3.3 折叠的状态转换

折叠指令将 $S_{t-2}$ 转换为 $S_{t-1}$：

$$
S_{t-2} \xrightarrow{f_t} S_{t-1}
$$

具体操作是将范围 $[k, t-1]$ 内的所有摘要块替换为单个新块 $s_{k,t-1} = \sigma_t$。最终更新后的上下文为：

$$
C_{t+1} = (Q, T, S_{t-1}, I_t), \quad \text{其中 } I_t = (e_t, a_t, o_t)
$$

### 6.4 训练方法：Fold-Generator + SFT

#### 6.4.1 训练数据生成

AgentFold 采用 **Fold-Generator** 生成训练数据：

1. **问题集**: 使用与 WebSailor 相同的问题集
2. **拒绝采样**（Rejection Sampling）：
   - 丢弃不符合格式要求的步骤
   - 丢弃包含过多环境错误的完整轨迹
3. **输出**: 高质量交互对集合 $\{(C_t, R_t^*)\}^N$

#### 6.4.2 监督微调（SFT）

- **基座模型**: Qwen3-30B-A3B-Instruct-2507（30B 总参数，3B 激活参数的 MoE 架构）
- **最大工具调用次数**: 100
- **训练目标**: 学习产生包含思维、折叠、解释、行动的结构化响应

#### 6.4.3 为什么需要训练

论文明确指出，即使是最强大的 LLM，也无法仅通过提示工程可靠地产生 AgentFold 所需的结构化响应。这是因为：
- 折叠操作需要对历史信息进行**元认知级别**的推理
- 需要同时权衡信息保留与上下文压缩的动态平衡
- 折叠范围的选择需要对任务进展有全局性理解

### 6.5 认知共生设计讨论

AgentFold 的一个关键设计决策是将折叠操作嵌入到推理-行动的主循环中，而非作为独立的后处理步骤：

**操作循环**：感知（Perceive）→ 推理（Reason）→ 折叠（Fold）→ 行动（Act）

这种**认知共生**（cognitive symbiosis）设计意味着：

1. **信息完整性**: 折叠发生在推理之后、行动之前，模型在折叠时已经完成了对当前状态的深度思考
2. **上下文自适应**: 折叠策略由模型的推理结果驱动，而非固定规则
3. **统一优化**: 折叠能力与任务执行能力在同一训练过程中联合优化
4. **精细凝缩的保护机制**: 通过精细凝缩模式，每条信息仅被压缩一次后以独立块形式保存，避免了反复总结导致的信息衰减

**关键发现**：

4. **广度与深度兼备**: WideSearch（62.1%）和 GAIA（67.0%）表现均衡，体现了良好的泛化能力

### 8.2 上下文动态分析

AgentFold 的上下文管理展现出显著的效率优势：

#### 上下文长度增长特性

- 上下文长度从初始 ~3.5K tokens 增长至 100 步后的 ~7K tokens，呈**亚线性增长**
- 对比 ReAct 的线性增长，100 步时 AgentFold 的上下文比 ReAct **小约 84K tokens**，节省约 **92%**
- 估计每个推理实例可节省约 **7GB** 显存

#### 摘要块数量

- 摘要块（block）数量同样呈亚线性增长，远慢于 ReAct 的线性增长
- 深度巩固操作周期性地合并多个块，有效控制了块数量

### 8.3 交互缩放特性

AgentFold 展示了卓越的缩放能力：

1. **一致性优势**: 30B 模型在所有工具调用限制下一致地超越 355B 的 GLM-4.5
2. **饱和抗性**: GLM-4.5 在超过 64 步后性能饱和，而 AgentFold 可持续改善至 256 步
3. **500 步扩展**: 扩展至 500 步时，上下文长度基本保持在 20K 以下
4. **非单调性**: 上下文长度呈现非单调变化特征，体现了深度巩固的**自我纠正**能力——当模型识别到失败路径时，大幅压缩上下文，为新策略腾出空间

### 8.4 案例研究

#### 深度巩固的实际应用

在一个具体案例中，步骤 6 至 16 的探索均以失败告终。在步骤 17，AgentFold 执行了深度巩固操作：

- 将整个 **11 步失败序列**压缩为一条总结性摘要
- 在总结中明确标注失败原因
- 随后**转向全新的调查策略**
- 展示了模型对**自身轨迹进行推理**并**从失败中学习**的能力

#### 上下文状态演化示例

| 步数 | 多尺度状态摘要结构 |
|------|-------------------|
| Turn 5 | `[Step 0], [Compressed Step 1 to 2], [Step 3]` |
| Turn 19 | `[Compressed Step 0], [Compressed Step 1 to 2], ..., [Compressed Step 6 to 16], [Step 17]` |
| Turn 30 | `[Compressed Step 0], ..., [Compressed Step 21 to 27], [Step 28]` |

此演化过程清晰地展示了：
- 精细凝缩如何将单步信息压缩保存
- 深度巩固如何周期性地压缩多步序列
- 近期步骤保持精细粒度，远期步骤逐步合并为粗粒度摘要

## 9. 与相关工作的对比

### 9.1 与 ReAct 系列的对比

| 维度 | ReAct | AgentFold |
|------|-------|-----------|
| 上下文管理 | 被动积累原始历史 | 主动折叠管理 |
| 上下文增长 | 线性增长 | 亚线性增长 |
| 100步上下文 | ~91K tokens | ~7K tokens |
| 信息保留 | 完整但冗余 | 多尺度选择性保留 |
| 长程扩展性 | 受上下文窗口限制 | 可扩展至 500 步 |

### 9.2 与固定摘要方法的对比

| 维度 | 固定摘要 | AgentFold |
|------|---------|-----------|
| 压缩策略 | 每步全量重新总结 | 选择性多尺度折叠 |
| 信息丢失 | 指数衰减（100步后 36.6%） | 精细凝缩保护关键信息 |
| 粒度控制 | 固定粒度 | 动态自适应粒度 |
| 管理方式 | 规则驱动 | 学习驱动 |

### 9.3 与 ContextFolding 的比较

AgentFold 与 ContextFolding（Zhong et al., 2025）在名称和理念上有相似之处，但存在重要区别：

- **ContextFolding**: 聚焦于通过折叠提升 API 调用场景的 KV cache 效率，本质上是一种**推理优化**技术
- **AgentFold**: 聚焦于 Web 智能体的**认知级别上下文管理**，将折叠作为推理循环的有机组成部分，强调多尺度信息管理和从失败中学习的能力

### 9.4 与大规模模型的效率对比

AgentFold-30B-A3B 以仅 3B 的激活参数量，在 BrowseComp 上超越了 DeepSeek-V3.1-671B（37B 激活）和 GLM-4.5-355B，体现了**上下文管理比纯粹扩大模型规模更为有效**的核心洞察。

## 10. 可能的欠缺与不足

1. **折叠决策的不可逆性**: 深度巩固一旦执行，被压缩的细节将无法恢复。如果模型在某一步做出了错误的折叠决策（例如过早合并了仍然重要的信息），可能对后续推理产生不可逆的负面影响。

2. **训练数据依赖性**: Fold-Generator 的数据质量直接决定了模型的折叠能力。论文未详细讨论训练数据的规模、多样性以及对不同领域任务的覆盖程度。

3. **评测基准的局限**: 主要评测集中在信息检索类 Web 任务（BrowseComp、WideSearch、GAIA），对其他类型的长程任务（如多步表单填写、复杂交互式网页操作等）的泛化能力尚未验证。

4. **折叠策略的可解释性**: 虽然提供了案例研究，但缺乏对折叠策略的系统性分析——模型在何种条件下倾向于选择精细凝缩 vs 深度巩固？是否存在可提炼的规律？

5. **与 RL 训练的结合**: 论文仅使用 SFT 训练，未探索强化学习（如 GRPO、PPO）对折叠策略优化的潜在提升。折叠操作作为一种离散决策，可能从基于结果奖励的 RL 训练中显著受益。

6. **多模态场景**: 当前方法主要处理文本形式的 Web 交互，对包含复杂视觉元素（如图表、动态页面）的场景适用性未知。

7. **基座模型依赖**: 论文基于 Qwen3-30B-A3B 进行训练，AgentFold 框架对不同基座模型的迁移性和兼容性未经验证。

8. **信息丢失的量化分析**: 虽然提供了理论分析（1% 丢失率），但缺乏对实际运行中信息丢失率的实证测量。精细凝缩模式下单次压缩的实际信息损失率未知。

---

## 11. 总结

AgentFold 提出了一种以**主动上下文管理**为核心的新型智能体范式，从根本上改变了长程 Web 智能体处理上下文的方式。其核心创新在于：

1. **范式转变**: 将上下文从"被动日志"重新定义为"动态认知工作空间"，智能体学会主动塑造自身的记忆
2. **多尺度折叠**: 通过精细凝缩和深度巩固两种模式，在信息保留与上下文压缩之间实现了优雅的平衡
3. **认知共生**: 将折叠操作嵌入推理-行动循环，使上下文管理成为推理过程的有机组成部分
4. **卓越效率**: 100 步后上下文仅 ~7K tokens（节省 92%），可扩展至 500 步，30B 模型超越 671B 模型

AgentFold 的成功表明，在长程智能体设计中，**上下文管理的质量比模型规模更为重要**。这一洞察对未来智能体系统的设计具有深远的指导意义——与其不断扩大模型容量来容纳更多原始信息，不如教会模型更智慧地管理和利用有限的认知资源。
